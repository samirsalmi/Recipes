# Backend map (FastAPI)

Multi-user API with JWT auth (see [database.md](database.md) for the schema). Every account
belongs to exactly one **household**; the meal plan, groceries and activity feed belong to the
household, never the user, and every household endpoint resolves "my household" from the token
(`get_membership`), never from a client-supplied id. The grocery list is computed live from the
plan (pure functions in `backend/app/groceries.py`); only marks/extras/range and the at-home amounts are stored. Recipes
are model v2 (mealTypes, diet flags, ingredient group/note/optional/aisle, step text/timerMinutes,
source, imageCredit, traditional, budget). System recipes come from `content/recipes/*.json` via the content importer.
Database: PostgreSQL 18 (local dev cluster on port 5434; psycopg 3); tests use SQLite or `TEST_DATABASE_URL`.
Schema changes go through Alembic (`backend/migrations/`), not create_all. See `backend/README.md`.

## Start here by task

| Task | Go to |
|---|---|
| Add or change a recipe field | `backend/app/schemas.py` `RecipeIn`/`RecipeUpdateIn` (API) and `ContentRecipe` (content files), `backend/app/recipe_data.py` `build_data()` (the stored blob); frontend `src/app/models/recipe.model.ts` must match |
| Ingredient merges wrong / wrong aisle on the grocery list | `backend/app/ingredients.py` - add an English alias to the dictionary (`canonical_name()`, `aisle_for()`); French and Arabic names go in `backend/app/ingredient_names.py` |
| Ingredient type-ahead (suggest across en/fr/ar, ranking, household custom names) and the strict "exact" test behind the form's auto-translate | `backend/app/ingredient_suggest.py` (`suggest_ingredients()`, `exact_match()`), endpoint `ingredient_suggest()` in `backend/app/routers/recipes.py`; tests `backend/tests/test_ingredient_suggest.py` |
| Ingredient written in French / Arabic, unknown-ingredient aisle picker, household aisle memory | names: `backend/app/ingredient_names.py`; matching + normalization: `backend/app/ingredients.py` (`normalize_text()`, `aisle_info()`, `is_known()`); units: `backend/app/groceries.py` `normalize_unit()`; endpoints `ingredient_check()`, `remember_ingredient_aisle()` in `backend/app/routers/recipes.py`; stamping `stamp_aisle()` in `backend/app/recipe_data.py` |
| Grocery maths: units, scaling, "+N more", "no longer needed", staples, optional | `backend/app/groceries.py` (`compute_needed()`, `build_list()`, `collect_optional()`, `format_amount()`, `resolve_have()`, `at_home_memory()`; aisle: dictionary first, then the household's remembered pick, then the stored aisle, then a keyword guess - see `_item_aisle()`), endpoints in `backend/app/routers/groceries.py` |
| Meal plan endpoints, copy week, fill suggestions | `backend/app/routers/plan.py` (`create_entry()`, `update_entry()`, `copy_week()`, `fill_suggestions()`) |
| Household membership, invite/join/leave, merge rule | `backend/app/households.py` (`get_membership()`, `join_household()`, `move_user_out()`), endpoints `backend/app/routers/household.py` |
| Live updates (what other members see) | `backend/app/households.py` `log_activity()` - call it in every plan/grocery mutation; polled via `GET /api/household/activity` in `backend/app/routers/household.py` `activity()` |
| Import a recipe from a URL | `backend/app/import_url.py` (`fetch_html()` with the SSRF guard `check_url()`, `parse_recipe_html()`), endpoint `import_url()` in `backend/app/routers/recipes.py` |
| (Re)load the curated recipes | `python -m app.content_import` - `backend/app/content_import.py` (`load_content()`, `resolve_images()`, `sync()`) |
| Demo data for a walkthrough | `python -m app.demo` - `backend/app/demo.py` `run()` |
| Change the DB schema | Edit `backend/app/models.py`, then `alembic revision --autogenerate -m "..."` and `alembic upgrade head` (see `backend/README.md`) - never rely on create_all |
| Change auth rules or token lifetime | `backend/app/security.py` (`hash_password()`, `create_access_token()`, `get_current_user()`, `get_current_user_optional()`, `require_admin()`), `backend/app/routers/auth.py` |
| Change CORS, DB, Redis, Cloudinary settings | `backend/app/config.py` `Settings`, read from backend/.env (see `backend/.env.example`) |
| Change image upload (Cloudinary, always AVIF) | `backend/app/routers/images.py` `upload_image()`; the importer uploads through `upload_image()` in `backend/app/content_import.py` |
| Tests | `backend/tests/` (pytest on in-memory SQLite by default, or PostgreSQL via TEST_DATABASE_URL; Redis off; `backend/tests/conftest.py` `add_system_recipe()`); run `python -m pytest` in backend/ with `backend/requirements-dev.txt` installed |
| Create the database + app role | `backend/scripts/create_db.py` `main()` (needs a superuser URL) |

## Gotchas

- Localization: the API never translates recipe text. Ingredient responses carry `name` (as typed), `canonical`, `known`, `names`; grocery items/extras/optional extras carry `names` and structured `neededAmount`/`remainingAmount`/`amountParts` (the English `*Label` strings remain for old clients); activity payloads carry structured fields (`title`, `act`, `names`...) next to the English `summary`. Optional per-recipe `translations` ({en|fr|ar: {name, description, steps, tips}}) is stored in the data blob and only returned.

- Have-at-home (`shopping_have`) is per trip and never mixed into `purchased_qty`: remaining = max(0, needed - have - purchased); `covered` = done with only at-home amounts. Payload `atHome` lists orphan amounts (plan changed) so the client can show/clear them. Pantry state = `promoted_staples` (need) vs the household staples (have), so it is per trip and only covers staples the plan uses.
- No password reset (no email at all). Accounts are username/password.
- `Settings.secret_key` defaults to a dev placeholder; set `SECRET_KEY` in production.
- Cloudinary: a wrong API secret fails as `Invalid Signature` (500 from `/api/images`, or a `ContentError` from the importer), not a clean 401.
- Route order in `backend/app/routers/recipes.py`: fixed segments (`/mine`, `/import-url`, `/ingredient-check`, `/ingredient-suggest`, `/ingredient-aisles`) are declared before `/{recipe_id}`.
- `backend/app/routers/plan.py` and `backend/app/routers/groceries.py` answer 404 (not 403) for another household's entry/extra so ids can't be probed.
- `import_url.check_url()` resolves the host, then urllib resolves it again to connect: a DNS-rebinding host could in theory pass the check and connect elsewhere. Pinning the connection to the checked IP would close it.
- Grocery marks are keyed by `<canonical name>|<family>` (`part_key()` in `backend/app/groceries.py`). Changing `canonical_name()` for an ingredient would orphan existing marks, so `build_list()` also honors marks under each part's `legacy_keys` (from `legacy_canonical_name()`; current key wins, legacy marks are summed, and the unmark endpoint in `backend/app/routers/groceries.py` deletes them too). When you re-route an existing spelling to a new canonical name, add it to `_LATE_ALIAS_TEXTS` in `backend/app/ingredients.py`. French/Arabic names and new canonicals live in `backend/app/ingredient_names.py` and are not part of the legacy table, so a name that used to be its own line ("la farine") gets its old key from `legacy_canonical_name()`; Arabic names had no old key (they normalized to ""). Never add FR/AR/EN entries by editing `_DICTIONARY_V1`; a name the original dictionary already resolved must keep its canonical key (tested in `backend/tests/test_groceries_logic.py`).
- The default test run is SQLite, production is PostgreSQL: use the `JSONType`/`TS` aliases, `true()`/`false()`/`func.now()` server defaults and plain SQLAlchemy constructs (no dialect-only SQL), and run the suite with TEST_DATABASE_URL before trusting a schema change.
